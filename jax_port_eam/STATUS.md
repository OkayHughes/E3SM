## How to resume (the loop that produced all of the above)

1. Pick the next item from PORTING_PLAN.md (finish CLUBB slice E, then
   F/G/H per the slicing plan; after CLUBB: vertical-diffusion stack,
   aerosol activation/hetfrz standalone goldens, intr layers,
   Tier-1.5 chains across schemes, Tier-2 on a supported machine).
2. The proven workflow per scheme is METHODOLOGY.md §"Workflow" —
   in this session it was executed by subagents given a standard
   prompt: read METHODOLOGY.md + the most recent worked example
   (harness/build_<X>.py + drivers/<X>_driver.F90 +
   gen_<X>_golden.py) + the relevant eam_jax modules and tests;
   components/ read-only; stubs infrastructure-only (abort-only
   placeholders allowed if provably never executed); constants
   verbatim; f2py builds ONLY in the scream-dev container
   (`docker exec -w /work/E3SM/jax_port_eam/harness scream-dev
   python3 build_<X>.py`); pytest on the host; golden metadata records
   every namelist value + git SHA; replay target rtol 1e-12/atol 0
   with measured, documented exceptions; Tier-0 properties; the
   supervising session independently re-runs the full suite before
   committing (one scheme per commit).
3. Environment gotchas are all recorded in METHODOLOGY.md
   ("Environment" section): container-only f2py, f2cmap kinds,
   -ffp-contract=off, macOS dlopen trap.

## Things a future session should NOT re-litigate

- gfortran FMA contraction and glibc-vs-XLA 1-ulp libm differences are
  the standing explanation for few-ulp replay tails; several were
  root-caused explicitly (see zm_microphysics/zm_conv/rrtmgp commit
  messages). fbuild compiles with -ffp-contract=off for this reason.
- Namelist corrections discovered vs naive defaults: clubb_C14=2.5,
  c_K10=c_K10h=0.35, wpxp_L_thresh=100.0 (case-insensitive
  build-namelist lookup), EAMv3 ipdf_call_placement=2, zvir=1.608
  exactly inside ZM. All recorded in golden metadata / PORT_NOTES.
- Data files: SCREAM's rrtmgp k-distribution + P3 v4.1.1 tables under
  ../e3sm-inputdata/atm/scream are reused; EAM cloud-optics tables
  were fetched into ../e3sm-inputdata/atm/cam/physprops (sha256s in
  golden metadata); the Beres04 mfcc file is absent — its golden uses
  a synthetic table (pure input data).
- fmod/ and build/ are gitignored (rebuild in the container on
  demand); golden/*.npz ARE committed.
